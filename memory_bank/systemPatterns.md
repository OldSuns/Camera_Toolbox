# 系统模式

## 架构模式

### 1. 分层架构 (Layered Architecture)
```
┌─────────────────────────────────────┐
│           表示层 (UI Layer)          │
│  - Screens (页面)                   │
│  - Widgets (组件)                   │
│  - Dialogs (对话框)                 │
├─────────────────────────────────────┤
│         业务逻辑层 (Business Layer)  │
│  - Providers (状态管理)             │
│  - Services (业务服务)              │
│  - Models (数据模型)                │
├─────────────────────────────────────┤
│         数据访问层 (Data Layer)      │
│  - File I/O (文件操作)              │
│  - Shared Preferences (本地存储)    │
│  - Platform Channels (平台通道)     │
└─────────────────────────────────────┘
```

### 2. 状态管理模式
- **Provider + ChangeNotifier**: 轻量级状态管理
- **Scoped State**: 每个功能模块独立管理状态
- **Reactive Updates**: 自动UI更新机制

### 3. 并发处理模式

#### Isolate使用模式

```dart
  return await compute(_parseExifDataInIsolate, filePath);
}

// 模式2: 长时间运行任务
Isolate? _isolate;

final _receivePort = ReceivePort();
```

#### 异步处理模式
- **Future/await**: 标准异步操作
- **Stream**: 文件列表和进度更新
- **Completer**: 复杂异步流程控制

### 4. 分页加载与多级缓存模式 (Paginated Loading with Multi-Level Cache Pattern)

- **模式描述**: 此模式旨在解决移动端或桌面端应用在需要显示大量数据（特别是需要昂贵计算才能渲染的媒体文件，如图片、视频）时的常见性能瓶颈。它通过结合"按需分页加载"和"多级缓存"策略，实现了快速的初始加载、流畅的滚动体验和高效的资源利用。

- **核心组件**:
    - **UI Controller (e.g., `ScrollController`)**: 监听用户的交互（如滚动），当达到预设的阈值（如列表末尾）时，触发数据加载事件。这是用户驱动数据获取的起点。
    - **Data Provider (e.g., `LocalPickerProvider`)**: 系统的核心协调者。它负责：
        - 维护当前的分页状态（已加载的页数或项目数）。
        - 持有已加载的数据列表（通常是轻量级的数据，如文件路径或ID，而非完整数据）。
        - 封装和管理多级缓存的访问逻辑。
        - 调用后台工作单元执行耗时操作。
    - **Multi-Level Cache**: 一个分层的缓存系统，用于最小化延迟和计算开销。
        - **内存缓存 (Memory Cache)**: 提供最快的访问速度，通常使用 `Map` 实现。用于存放最常用或最近访问的数据。生命周期通常与应用会话或特定页面绑定。
        - **磁盘缓存 (Disk Cache)**: 提供持久化存储，避免应用重启后重复生成数据。速度慢于内存缓存但快于重新计算。
    - **Background Worker (e.g., `Isolate`)**: 在独立的后台线程或进程中执行耗时操作（如图片解码、缩略图生成、文件压缩等），避免阻塞UI主线程，确保界面流畅。

- **适用场景**:
    - **相册应用**: 如本项目中的"本地选片"功能，需要展示设备上成百上千张图片。
    - **社交媒体Feed流**: 无限滚动加载新的帖子、图片或视频。
    - **文件管理器**: 显示包含大量文件的目录。
    - **电商应用**: 商品列表的无限滚动加载。
    - **新闻或文章列表**: 按需加载更多条目。

### 5. 双列对比模式 (Dual-Column Comparison Pattern)

- **模式描述**: 此模式用于实现两个相似数据集的并排对比展示，允许用户同时查看和比较两个不同的数据实例。该模式通过响应式布局和独立的状态管理，实现了灵活的对比视图。

- **核心组件**:
   - **对比开关控制器**: 一个UI控件（如Switch或ToggleButton），用于切换对比模式的启用/禁用状态。
   - **双列布局管理器**: 根据对比模式状态动态调整界面布局，从单列布局切换到双列布局。
   - **独立选择器管理**: 在对比模式下，为每一列提供独立的数据选择器，允许用户分别选择要对比的数据实例。
   - **数据展示协调器**: 协调两个数据实例的展示，确保它们以一致的格式和对齐方式显示，便于用户对比。

- **实现要点**:
   - **响应式布局**: 使用Flutter的`LayoutBuilder`或`MediaQuery`来根据屏幕尺寸和对比模式状态动态调整布局。
   - **状态隔离**: 在对比模式下，确保每列的选择状态和数据展示是独立的，避免相互干扰。
   - **UI一致性**: 在对比视图中，确保两个数据实例的展示格式、字段排列和视觉样式保持一致，便于用户进行直观对比。

- **适用场景**:
   - **产品规格对比**: 如本项目中的相机数据对比功能，允许用户并排比较两个不同相机型号的规格参数。
   - **价格对比**: 电商平台中对比不同商品的价格和特性。
   - **版本对比**: 软件或文档的不同版本之间的功能对比。
   - **配置对比**: 硬件或服务的不同配置选项对比。

### 6. 批量重命名模式 (Batch Rename Pattern)

- **模式描述**: 此模式用于实现多种策略的批量文件重命名功能，通过TabView组织不同的重命名策略，提供统一的文件管理和预览机制。

- **核心组件**:
   - **策略管理器**: 管理不同的重命名策略（替换、追加、自动序号、EXIF命名），每种策略有独立的配置和实现。
   - **文件列表管理器**: 管理待重命名的文件列表，支持文件拖放、文件夹选择、排序和预览。
   - **预览引擎**: 根据当前选择的策略和配置，实时预览重命名效果。
   - **执行引擎**: 在Isolate中执行重命名操作，避免UI冻结，并提供进度反馈。
   - **撤销管理器**: 管理重命名操作的历史记录，支持撤销上一次操作。

- **实现要点**:
   - **策略模式**: 使用策略模式实现不同的重命名策略，便于扩展和维护。
   - **响应式预览**: 实时预览重命名效果，让用户在执行前确认结果。
   - **异步执行**: 使用Isolate进行重命名操作，确保UI流畅。
   - **错误处理**: 提供详细的错误信息和处理机制，确保操作的可靠性。
   - **撤销功能**: 支持撤销操作，提高用户体验。

- **适用场景**:
   - **文件管理**: 批量重命名照片、文档等文件。
   - **数据整理**: 整理和规范化文件命名。
   - **自动化处理**: 根据特定规则自动重命名文件。
