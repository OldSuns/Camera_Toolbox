# 当前活动上下文

**最后更新时间:** 2025-07-24

**当前焦点:** 批量重命名功能中"自动序号"的序号依据问题修复

## 问题描述
在批量重命名功能中，"自动序号"的序号依据应该遵从"排序方式"的规则，按显示在用户界面的顺序进行排序序号。但在实际使用中发现，当启用"同名合并"功能时，序号分配未遵循用户选择的排序规则。

## 问题分析
1. 当`mergeSameName`为true时，序号分配是基于`_mergedNumberingCache`缓存计算的
2. 在旧的`_precalculateMergedNumbering`方法实现中，它首先获取文件列表中所有唯一的基本名称，然后对这些基本名称进行排序
3. 这导致了序号分配是按照基本名称的字母顺序，而不是按照文件在排序后列表中的顺序

## 解决方案
修改`_precalculateMergedNumbering`方法，使其按照文件在排序后列表中的顺序来分配序号：
1. 遍历排序后的文件列表
2. 对于每个文件，检查其基本名称是否已分配组索引
3. 如果未分配，则按顺序分配新的组索引
4. 将组索引存储在`_mergedNumberingCache`中

## 实施结果
已成功修复`_precalculateMergedNumbering`方法，现在当启用"同名合并"功能时，序号分配会正确遵循用户选择的排序规则。
