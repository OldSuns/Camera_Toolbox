# 决策日志

## 2025-08-11: 图像压缩功能技术选型

- **决策**: 选择 `simple_native_image_compress: ^3.0.2` 作为图像压缩的核心依赖。
- **理由**:
    - 该插件为原生实现，在Windows和Android平台上具有较好的性能和兼容性。
    - 满足了指定压缩质量和调整尺寸的核心需求。
    - 社区活跃度尚可，能够满足当前项目需求。
- **备选方案**:
    - `flutter_image_compress`: 功能强大，但主要针对移动端，桌面端支持不明确。
    - dart:io + image: 功能全面，但纯Dart实现可能在批量处理大量图片时性能不及原生插件。
- **决策者**: NexusCore
- **状态**: 已决定

## 2025-08-11: 图像压缩 Isolate 生命周期管理决策

- **决策**:
    1.  **按需创建与销毁**: Isolate 池的生命周期与压缩任务绑定，在任务开始时创建，结束后立即销毁，而不是在应用启动时就初始化。
    2.  **State级服务管理**: 将 `ImageCompressService` 实例的管理从 `Provider` 的 `create` 回调提升到 `State` 对象中，使用 `ChangeNotifierProvider.value` 进行注入，以避免因UI重建导致的服务实例泄漏。
    3.  **优雅关闭与强制终止**: 实现一个包含 `shutdown` 信号的优雅关闭机制，并辅以超时强制终止，确保 Isolate 能够被彻底清理。
- **理由**:
    - **资源效率**: “按需创建”避免了不必要的常驻资源占用，提高了应用的启动速度和内存效率。
    - **稳定性**: “State级服务管理”和“优雅关闭”机制彻底解决了因生命周期管理不当和异常路径处理不全导致的资源泄漏问题，显著提高了应用的健壮性。
- **决策者**: NexusCore (基于 code-developer 的分析)
- **状态**: 已实施
